# 通用跨学科完整硕士论文升级路线图

**日期：** 2026-07-15  
**目标：** 不把成功限制为 RAG 或计算机领域；系统必须能够为任意学科建立正确的方法论、协调真实研究资源，并在证据充分时完成符合院校要求的完整硕士论文。

## 1. 对现状结论的纠正

阶段 0–7 的真实运行只证明了：系统能在受控计算检索课题中完成一个可复现 pilot 研究报告。它没有证明以下能力：

- 人文解释、史料批判、哲学论证和数学证明；
- 访谈、焦点小组、参与式观察和质性编码；
- 问卷、观察研究、因果推断、临床或社会科学统计；
- 湿实验、设备实验、田野调查、受试者招募和伦理审批；
- 系统综述、范围综述、元分析和证据分级；
- 符合具体院校、专业、篇幅、章节和引用规范的完整硕士论文。

因此，“限定领域可完成”不是最终完成状态。

## 2. 当前跨学科硬缺口

1. Research Contract 把课题默认建模为 empirical hypothesis testing。
2. `task_type` 和 Agent 能力矩阵以软件系统、计算实验为中心。
3. 实验执行器只有检索/RAG 模板，无法表达其他研究方法。
4. 对不能由软件执行的资源，没有统一的责任人、完成凭证和阻塞状态。
5. 伦理审批、参与者同意、隐私、动物实验和受监管材料未成为执行硬门。
6. 人文和理论研究被迫提供 treatment、baseline 和数值 metric，认识论错误。
7. 最终报告没有绑定目标院校的学位论文规范、篇幅和完整章节验收。
8. 现有 benchmark 只覆盖科研诚信和计算实验，没有跨学科完整论文金标准。

## 3. 不可伪造的“通用能力”定义

通用能力不等于软件能够亲自做所有物理动作。对于湿实验、临床、田野和访谈，系统必须：

1. 正确设计并预注册方案；
2. 列出设备、场地、材料、人员、审批和数据要求；
3. 把需要人类或机构完成的动作分派为可审计任务；
4. 在收到真实记录、数据和审批凭证前保持阻塞；
5. 验证输入、执行分析、保留失败和负面结果；
6. 只有全链路通过才形成完整硕士论文。

把缺失资源标记为“需要人工/机构完成”是通用科研系统的正确行为；伪造实验记录不是自治。

## 4. 分阶段升级

### 阶段 8：跨学科研究画像与双层可行性门

- 学科画像：broad field、field、subfield；
- 方法族：quantitative、qualitative、computational、experimental、systematic review、humanities、theoretical、design science、mixed methods；
- 认识论模式：假设检验、估计、探索、解释、证据综合、证明构造、artifact evaluation、理论构建；
- 资源计划：数据、语料、设备、实验室、参与者、软件、专业人员及其真实状态；
- 伦理计划：是否需要、审批状态、审批机构、敏感性和风险；
- 学位规范：院校、专业、语言、字数、章节、引用格式；
- 两个独立结论：`research_ready` 与 `master_thesis_ready`。

验收：至少八种方法族可被正确建模；解释性和理论研究不被强迫生成统计假设；缺资源/审批的课题 fail closed；论文规范缺失时只能输出 research report，不能宣称完整硕士论文。

### 阶段 9：通用研究工作包和方法执行器

- 用 research design、data acquisition、analysis、synthesis、thesis assembly 替代计算机中心任务语义；
- 定量：抽样、功效、测量、缺失值、稳健性、效应量与统计假设检查；
- 定性：招募、访谈提纲、转录、编码本、双人编码、饱和度、反身性和负例；
- 系统综述：协议注册、数据库、去重、双人筛选、质量评价、PRISMA、元分析；
- 人文：一手史料、版本/出处、文本批判、解释框架、反论证与互证；
- 理论：定义、引理、证明依赖、反例搜索、形式或独立检查；
- 实验：计算实验、设备/湿实验的人机执行包与原始记录验证；
- 混合方法：并行/顺序设计、联合展示和整合推论。

### 阶段 10：完整硕士论文装配与院校约束

- 章节级论证图和字数预算；
- 研究问题—方法—结果—讨论闭环；
- 表格、图、附录、数据/代码/材料声明；
- 引文样式与参考文献一致性；
- 摘要、关键词、目录、术语、跨章一致性；
- 院校模板和盲审要求；
- 独立导师、方法专家、统计/质性专家与诚信审查。

### 阶段 11：跨学科真实端到端验收

至少完成并保存下列不同范式的真实项目：

1. 计算/工程实证；
2. 社会科学定量或公开数据观察研究；
3. 系统综述；
4. 人文解释或理论研究；
5. 质性或混合方法项目（需要真实参与者时允许经审计的人机协作）。

每个项目必须有真实来源、方法专用质量门、原始材料、完整论文、独立审查和可追溯清单。任何一个范式只能生成模板、虚构数据或缺少关键章节，都不能宣称达到最终目标。

## 5. 最终停止条件

只有同时满足以下条件才停止：

- 不依赖领域关键词硬编码来决定研究有效性；
- 八类方法画像和方法专用质量门均有正反例基准；
- 至少五个不同范式的真实端到端项目通过；
- 有外部资源的项目能正确协调人类/机构并验证返回材料；
- 完整硕士论文规范、章节、篇幅、证据、方法和审查全部通过；
- 系统对无法完成的环节保持阻塞，绝不通过编造文献、数据、审批或实验来“完成”。

在这些证据出现前，目标保持进行中。

## 6. 执行状态

- 阶段 8：已完成跨学科研究画像、资源/伦理门和论文可行性门。
- 阶段 9：已完成通用研究工作包、真实材料哈希和七类确定性分析适配器。
- 阶段 10：已完成完整硕士论文质量门、分章节写作和可追溯装配。
- 阶段 11A：已建立独立五范式真实运行验收器；当前结果为 **0/5**，因此最终目标仍未完成。
- 阶段 11B–11D：待执行五个真实项目并逐一通过验收，登记文件为 `benchmarks/thesis_projects.json`。
- 阶段 13U：已根据计算/工程范式首次真实运行修复章节生成死循环风险：补全改为最多两轮、正文专用、长度与错误单调改进，根任务终态后陈旧返工分支自动归档。真实运行已完成文献、研究设计、可复现实验与结果分析，但三个章节因旧补全策略未达 70% 字数硬门，尚未计入通过项目。
- 阶段 13V：论文章节返工改为携带完整上一版 `chapter`，使模型按独立审稿意见定点修改，不再每轮从 summary 重写整章；普通任务继续使用 6000 字符紧凑上下文。
- 阶段 13W：章节独立审稿改为“冻结证据优先、正文在后”的 48000 字符上下文，避免 24000 字符截断恰好删掉 allowed support 和实验工件；对已通过 schema 存在性校验的 support ID，确定性剔除“ID 不存在”式自相矛盾意见，但保留证据与段落语义不匹配的真实问题。
- 阶段 13X：必需根章节任一未通过时，运行必须在论文装配前 fail closed，记录失败章节并停止生成/发布总报告；已被通过新版替代的失败兄弟草稿不影响装配。
- 阶段 13Y：论文 `experiment:*` 支持对象补入冻结实验协议（变量、数据集、指标、基线、方法细节、停止条件和风险），使方法章从真实协议获取“100 字符窗口”等执行事实，不再从结果表猜测切分单位或实验设计。
- 阶段 13Z：论文装配按每个根章节解析最新通过返工版本，忽略历史失败草稿；写作收敛后根章节处于 `blocked`、`failed` 等任何非完成状态均阻断发布，禁止回退到非确定性总稿掩盖章节失败。
- 阶段 14A：修复英文必需章标题大小写导致有效篇幅误计为 0；研究循环把冻结论文契约中的最低受支持 claim 数与不同引用来源数纳入 `ready_to_report`，不足时生成一次合并证据覆盖动作，要求逐来源全文 passage 直接蕴含且禁止用缺失性 context note 凑数。
- 阶段 14B：章节最低篇幅由固定 70% 改为 `max(70%, 院校最低总字数/目标总字数)` 的同比预算，并在装配前复核最新通过版本的实际正文；解决章节分别过门但整篇仍低于院校下限的问题。
- 阶段 14C：受控研究循环的 token/成本预算仅统计 `[循环R*]` 动作及其返工链，不再被初始研究、论文章节和报告审稿消耗误伤；轮次、动作指纹与连续无进展闭锁保持不变，既允许必要补证也不放开死循环。
- 阶段 14D：研究动作执行入口复用研究循环的隔离预算统计，移除执行前仍按全 Run token 二次拒绝动作的旧口径，保证规划门与执行门对同一预算作出一致决定。
- 阶段 14E：研究循环新增动作只依赖已完成的非写作研究任务，禁止依赖 `thesis_chapter`/`report_writing`；避免补证动作与随后更新的章节依赖形成研究↔写作环。
- 阶段 14F：章节全部通过后按实际正文总词数检查院校最小/最大范围；若越界，选择相对章节预算偏差最大的最新通过章，在保留事实、support 和边界的前提下定点扩展或压缩，最多两轮，仍不达标则 fail closed。
