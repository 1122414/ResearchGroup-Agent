## 六、关键技术决策

### 6.1 搜索API选择建议

| API | 成本 | 质量 | 适用场景 | 推荐度 |
|-----|------|------|----------|--------|
| CrossRef | 免费 | 中 | 有DOI的论文 | ★★★★ 保留 |
| OpenAlex | 免费 | 中高 | 全领域 | ★★★★★ 保留 |
| arXiv | 免费 | 高(CS/物理) | 预印本 | ★★★★ 保留 |
| **Tavily** | $20/月 | 高 | 通用网络 | ★★★★★ **必须启用** |
| Serper | $50/月 | 很高 | Google搜索 | ★★★★ 强烈推荐 |
| SerpAPI Scholar | $50/月 | 极高 | Google Scholar | ★★★★★ 预算允许时 |
| DBLP | 免费 | 高(CS) | CS文献 | ★★★★ 推荐新增 |
| Semantic Scholar | 免费/付费 | 高 | 全领域 | ★★★ 启用 |
| PubMed | 免费 | 高(医学) | 生物医学 | ★★★ 按需 |

### 6.2 LLM调用成本预估（单次研究任务）

| 阶段 | 调用次数 | Token预估 | 成本(GPT-4o) |
|------|----------|-----------|-------------|
| Query改写 | 1-2次 | ~2K | ~$0.01 |
| 迭代Think/Plan | 3-5次 | ~10K | ~$0.05 |
| 相关性排序(LLM) | 1次 | ~5K | ~$0.03 |
| Grounded生成 | 1次 | ~15K | ~$0.08 |
| 导师审核 | 1-2次 | ~5K | ~$0.03 |
| **单任务总计** | ~10-15次 | ~40K | **~$0.20** |

与当前的单次调用相比增加约5-10倍成本，但质量提升巨大。

### 6.3 可选的成本优化

| 策略 | 节省 | 说明 |
|------|------|------|
| Think/Plan用小模型 | -40% | GPT-4o-mini 足够 |
| 关键词排序替代LLM排序 | -15% | 牺牲少量精度 |
| 搜索缓存 | -30% | 相似query复用结果 |
| 知识库预填充 | -20% | 热门领域预搜索 |

## 七、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Tavily/Serper API不稳定 | 搜索失败 | 多源fallback + 缓存 |
| 迭代搜索耗时过长 | 用户等待 | 并行搜索 + 超时控制 + 进度展示 |
| LLM仍然幻觉 | 输出不可信 | Grounding验证 + DOI检查 双重保障 |
| 成本超预期 | 不可持续 | 小模型降级 + 缓存 + 迭代次数限制 |
| 学术API变更 | 功能失效 | 抽象Provider层 + 降级策略 |
| 中文研究场景覆盖不足 | 找不到中文论文 | 知网/万方接入（长期）+ 用户种子 |

## 九、立即可执行的最小行动

如果只有1天时间，做以下改动即可看到显著改善：

```bash
# 1. 配置Tavily API Key (.env)
WEB_SEARCH_ENABLED=true
TAVILY_API_KEY=tvly-your-key

# 2. 增加搜索结果数
EVIDENCE_MAX_RESULTS_PER_SOURCE=15

# 3. 启用Semantic Scholar
SEMANTIC_SCHOLAR_ENABLED=true

# 4. 启用浏览器验证（如果环境允许）
BROWSER_RESEARCH_ENABLED=true
```

然后实现 `query_rewriter.py`（约200行代码），集成到 `evidence_pipeline_service.py`。

**仅这两步就能将文献搜索质量提升50-70%。**
