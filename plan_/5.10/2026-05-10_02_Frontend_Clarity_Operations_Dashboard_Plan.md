# 前端清晰化与运行监测控制台计划

**日期**: 2026-05-10  
**范围**: `frontend/src/app`, `frontend/src/lib`, `frontend/src/components`  
**优先级**: P0-P1

## 1. 目标

把前端从“提交任务后不知道发生了什么”改成“研究组运行控制台”。用户打开页面后应能一眼看懂：

1. 系统现在在哪个阶段。
2. 哪些任务已拆解，分别由谁负责。
3. 每个 Agent 当前状态。
4. 最新事件是什么。
5. 已花费多少 token、多少钱、多久。
6. 如何停止当前 Run。

## 2. P0 先修：中文可读性

当前前端多个文件中文文案疑似编码损坏，必须先统一替换为正常中文。

涉及文件：

1. `frontend/src/app/page.tsx`
2. `frontend/src/app/tasks/page.tsx`
3. `frontend/src/app/agents/page.tsx`
4. `frontend/src/app/outputs/page.tsx`
5. `frontend/src/lib/types.ts`
6. 后端返回给前端的中文错误、步骤文案也应同步修复。

要求：

1. 所有按钮、标题、状态标签、错误提示必须是人类可读中文。
2. `TASK_STATUS_LABELS`, `AGENT_STATUS_LABELS`, `RUN_STATUS_LABELS`, `SKILL_NAMES` 必须集中定义。
3. 前端不要直接展示枚举英文，除非作为调试辅助小字。

## 3. 新页面结构

### 3.1 首页 `/`

首页只负责创建研究任务，不再直接等待 `runAll` 完成。

流程：

1. 用户输入研究目标。
2. 点击“创建并开始运行”。
3. 前端调用 `POST /api/runs`。
4. 再调用 `POST /api/runs/{run_id}/start`。
5. 跳转到 `/runs/{run_id}`。

首页内容：

1. 研究目标输入框。
2. 示例目标按钮。
3. 最近 Run 列表：状态、创建时间、累计成本、继续查看按钮。
4. Mock 模式提示：当前为模拟模式或真实 LLM 模式。

### 3.2 运行详情页 `/runs/[run_id]`

这是最重要的新页面。

模块布局：

1. 顶部运行摘要
   - Run ID
   - 研究目标摘要
   - 当前状态
   - 当前阶段
   - 开始时间、更新时间、完成时间
   - 总耗时
   - “停止运行”按钮
2. 阶段进度条
   - 创建
   - 拆解任务
   - 调度分配
   - 执行任务
   - SubAgent
   - 导师审核
   - 生成报告
   - 完成
3. 成本监测表
   - 累计费用
   - 累计 token
   - LLM 调用次数
   - 平均耗时
   - 最近调用模型
4. 事件时间线
   - 倒序展示最新事件
   - 支持按阶段过滤
   - 每条事件显示时间、Agent、任务、说明
5. 任务执行表
   - 任务标题
   - 状态
   - 负责人
   - 协作者
   - 优先级/复杂度/可拆解度
   - 最新事件
6. Agent 活动区
   - Agent 名称
   - 状态
   - 当前任务
   - 负载
   - 技能亮点
7. 产出入口
   - 任务产出
   - SubAgent 产出
   - 审核结果
   - 最终报告

轮询策略：

1. Run 未完成时每 1-2 秒轮询 `summary/events/usage`。
2. Run 完成、失败、取消后停止轮询。
3. 轮询失败时显示错误，但不要清空已有数据。

### 3.3 任务看板 `/tasks`

保留状态列，但增强可解释性。

每张任务卡必须显示：

1. 标题。
2. 中文状态。
3. 负责人。
4. 当前阶段/最新事件。
5. 为什么分给该 Agent：主要匹配技能或调度分。
6. 是否有 SubAgent。
7. 产出数量/审核结果。

点击任务卡打开详情抽屉或下方详情面板：

1. 任务描述。
2. 所需技能条。
3. 调度信息。
4. 事件流。
5. 输出摘要。
6. 审核反馈。

### 3.4 Agent 页面 `/agents`

从静态卡片改成“课题组成员面板”。

每个 Agent 卡片显示：

1. 头像占位或像素角色占位。
2. 名称和角色：文献研究、工程实现、实验设计、数据分析、论文写作。
3. 当前状态。
4. 当前任务。
5. 负载。
6. 技能雷达/条形图。
7. 最近事件。

### 3.5 输出页 `/outputs`

当前输出页可以保留，但要增加：

1. 按任务过滤。
2. 按输出类型过滤。
3. 输出摘要优先，展开后再看 JSON。
4. 最终报告放在顶部，但不要用难读的纯 `pre` 占满页面。

## 4. 停止任务交互

“停止运行”按钮规则：

1. 仅在 `created/queued/decomposing/scheduling/executing/reviewing/reporting` 状态显示。
2. 点击后弹确认框：说明会停止后续任务，已经生成的产出会保留。
3. 调用 `POST /api/runs/{run_id}/cancel`。
4. 按钮进入 loading 状态，页面显示“正在请求停止”。
5. 后端状态变为 `cancelled` 后按钮禁用。

严禁：

1. 只停止前端轮询。
2. 只 Abort 当前 fetch。
3. 停止后把 Run 当失败处理；取消是独立状态。

## 5. 成本监测表

运行详情页必须有一张用户能看懂的成本表。

字段：

1. 时间。
2. 阶段。
3. 角色。
4. Agent。
5. 任务。
6. 模型。
7. prompt tokens。
8. completion tokens。
9. 总 token。
10. 费用 USD。
11. 耗时 ms。
12. 成功/失败。

顶部汇总：

1. 本次 Run 累计费用。
2. 累计 token。
3. LLM 调用次数。
4. 最慢调用。
5. 失败调用数。

Mock 模式：

1. 显示“Mock 模式，费用为 0”。
2. token 可以显示估算值。

## 6. UI 风格要求

这是科研协作系统，不是营销页。

要求：

1. 第一屏直接进入操作和监控，不做大 hero。
2. 页面布局偏工作台：信息密度适中，可扫描。
3. 使用清晰标签、表格、时间线、状态色。
4. 不使用大面积渐变、装饰性卡片堆叠。
5. 卡片圆角不超过现有 shadcn 风格。
6. 对长标题和长任务描述做截断与展开，不能溢出。

## 7. 禁止事项

1. 禁止先做像素动画而不修运行详情页。
2. 禁止把所有信息塞到首页。
3. 禁止让用户只能看 JSON。
4. 禁止把成本藏在浏览器 console 或后端日志。
5. 禁止引入大型状态管理库；当前规模用 React state + hooks 即可。
6. 禁止改成 WebSocket 强依赖；轮询先实现。

## 8. 验收标准

1. 用户创建任务后 2 秒内跳转到 `/runs/{id}` 并看到当前阶段。
2. Run 执行时，事件时间线持续新增。
3. 成本表能显示 Mock 记录或真实 LLM 记录。
4. 点击停止后页面状态变为取消中/已取消。
5. `/tasks` 中每个任务卡能看懂负责人、状态、最新事件。
6. 前端所有中文可读，不再出现乱码。
