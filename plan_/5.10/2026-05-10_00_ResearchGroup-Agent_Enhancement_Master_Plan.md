# ResearchGroup-Agent 增强总计划

**日期**: 2026-05-10  
**目标读者**: OpenCode / 后续实现 Agent  
**目标**: 把当前 MVP 从“能跑完流程”升级为“用户能实时看懂系统正在做什么、花了多少成本、从哪里可以停止”，并为后续像素风课题组办公室监控打好接口和数据基础。

## 1. 当前问题摘要

基于当前代码结构和 README 跑法，现状有以下明显问题：

1. 前端首页调用 `createRun` 后立即 `runAll`，用户只能等待完整流程结束，无法看到拆解、调度、执行、审核、报告生成的中间过程。
2. `runs.current_step` 只有一条当前步骤文案，没有结构化事件流；前端无法展示“刚刚发生了什么、下一步是什么、哪个 Agent 正在处理哪个任务”。
3. 没有成本账本。真实 LLM 模式下没有记录模型、token、调用次数、单次估算费用、累计费用、耗时。
4. 没有任务或 Run 停止能力。后端 `run_all` 是单请求串行执行，前端无法中止服务端流程。
5. 前端中文文案疑似编码损坏，用户肉眼不可读，这是第一优先级修复项。
6. 当前任务看板只是状态列堆叠，不能解释状态含义、任务归属原因、Agent 活动和产出脉络。
7. 像素办公室愿景需要实时状态数据，但当前系统没有稳定的 Agent activity API、坐标/办公室/动画状态契约。

## 2. 目标体验

用户发布研究目标后，前端必须清楚呈现：

1. 当前 Run 处于哪个阶段：创建、任务拆解、调度、执行、SubAgent、导师审核、报告生成、完成、失败、取消。
2. 每个阶段发生了什么：开始时间、结束时间、耗时、执行者、输入摘要、输出摘要、错误信息。
3. 每个 Agent 此刻在干什么：空闲、思考、执行任务、等待 SubAgent、审核、阻塞、完成。
4. 每个任务为什么分给某个 Agent：匹配分、主要技能、协作者、SubAgent 是否被触发。
5. 当前累计成本：调用次数、token 估算/真实 token、模型、费用、耗时、失败重试。
6. 用户可以从前端停止一个 Run；停止后系统进入 `cancelling/cancelled`，不再继续执行后续任务。
7. 像素办公室页面能用动画和气泡解释系统状态，但底层仍以结构化状态和任务板为准。

## 4. 开发优先级

### P0 必须先做

1. 修复前端所有不可读中文文案。
2. 将 `run_all` 从“黑盒长请求”改造成可观测流程：最少要有 `run_events` 表和 `GET /api/runs/{id}/events`。
3. 增加 Run 取消能力：`POST /api/runs/{id}/cancel`，执行循环每个阶段检查取消标记。
4. 增加成本/耗时记录：即使 Mock 模式也要产生 0 成本或估算记录，保证前端表格能工作。
5. 前端首页改为“创建 Run -> 进入运行详情页 -> 轮询状态”，不要继续阻塞等待 `run_all` 返回。

### P1 第二阶段

1. 新增 `/runs/[id]` 运行详情页：阶段时间线、任务流、Agent 当前状态、成本表、停止按钮。
2. 改造 `/tasks` 为可解释任务板：每张任务卡展示状态原因、负责人、当前步骤、最后事件。
3. 增加 Run 级摘要：总耗时、任务总数、完成数、需修改数、失败数、SubAgent 数、累计成本。
4. 为像素办公室提供 `GET /api/monitor/office-state?run_id=...` 聚合接口。

### P2 第三阶段

1. 像素办公室监控页：办公室地图、导师办公室、研究生独立办公室、公共任务看板。
2. Agent 小人按状态移动或切换动画，气泡显示当前任务和最新事件。
3. 可从像素办公室点开 Agent 或任务详情，跳到运行详情/任务详情。

### P3 后续预留

1. WebSocket / SSE 实时推送。
2. 自定义像素资产上传与管理。
3. 多用户、权限、公开分享、桌面宠物、外部 Agent 加入。
4. 外部工具接入、长期记忆、LangGraph/AutoGen 等编排引擎替换。

## 5. 总体边界

本次计划聚焦本地 MVP 增强，不做以下内容：

1. 不做账号系统、权限系统、OAuth、团队共享。
2. 不接 Zotero、Overleaf、Notion、GitHub Issue 等外部工具。
3. 不做 WebSocket 强依赖，先用轮询实现稳定可用。
4. 不引入复杂数据库迁移框架；继续沿用 SQLite 初始化脚本，但要兼容旧库缺列/缺表。
5. 不改变 Agent 的科研能力边界，不做真实论文检索、模型训练、集群调度。
6. 不让 SubAgent 直接进入最终报告；SubAgent 结果仍必须经研究生 Agent 整合和导师审核。
7. 不直接复制 Star-Office-UI 的美术资产；可参考其“状态可视化、角色动画、多人状态看板”的产品模式。参考项目: https://github.com/ringhyacinth/Star-Office-UI

## 6. 推荐执行顺序

1. 执行文档 01：先补后端事件、成本、取消、状态接口。
2. 执行文档 02：前端先变清楚、可停止、可看成本。
3. 执行文档 05：用验收用例检查接口和流程稳定性。
4. 执行文档 04：统一角色设定、标签、资产规格。
5. 执行文档 03：接入像素办公室监控。
